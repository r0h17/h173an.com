# h173an.com

Static site on GitHub Pages. Domain registered at Squarespace, DNS pointed at
GitHub.

Its real job is hosting a Tesla Fleet API public key so Home Assistant can
control the Powerwall without a Teslemetry subscription. See
`../homeassistant-powerwall`.

## Layout

    .nojekyll                                            REQUIRED, see below
    CNAME                                                h173an.com
    index.html                                           placeholder page
    .well-known/appspecific/com.tesla.3p.public-key.pem  the Tesla key

## Do not delete .nojekyll

GitHub Pages runs Jekyll by default, and **Jekyll silently drops every
directory beginning with a dot** — including `.well-known`. The key would
404 with no error anywhere, and Tesla registration would fail for no visible
reason. The empty `.nojekyll` file disables Jekyll and serves the tree
verbatim.

## The key

PEM-encoded secp256r1 public key. Its private half is `tesla_fleet.key`
inside Home Assistant (`/config/tesla_fleet.key`), generated by the
`tesla_fleet` integration. A public key is not a secret; the private half
never leaves HA.

Tesla requires it at exactly:

    https://tesla.h173an.com/.well-known/appspecific/com.tesla.3p.public-key.pem

and the root domain must match the Allowed Origin set on the application at
developer.tesla.com.

Verify a deploy end to end — reachable, parseable, and matching HA's private
key — with:

    ../homeassistant-powerwall/fleet/verify.sh tesla.h173an.com

## DNS — use the subdomain, not the apex

One record, at Squarespace:

| type | host | value |
|---|---|---|
| CNAME | `tesla` | `r0h17.github.io` |

Then Settings → Pages → Custom domain `tesla.h173an.com` → **Enforce HTTPS**
(the checkbox can take up to 24h to become available while the certificate
is issued). Tesla will not accept the key over plain HTTP.

### Why not the apex

Squarespace would not publish custom `A` records on `@`. All four GitHub
IPs were saved in the DNS UI, but the authoritative nameservers kept
answering with the Squarespace parking IP `185.149.22.187` for minutes
afterwards. The `AAAA` records published instantly, so this is a locked
default `A` record on the apex, not propagation lag.

CNAMEs publish on this zone without trouble, and pointing a subdomain at
`<user>.github.io` is GitHub's recommended setup anyway. The leftover apex
`A`/`AAAA` records are inert — nothing claims `h173an.com` on Pages — and
can be cleaned up whenever.

Tesla is fine with this: HA's config flow asks for "the domain name you
intend to host your public key on", which "should be the same or a
subdomain of your origin domain". Origin stays `https://h173an.com`.
